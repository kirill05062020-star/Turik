# Отчёт о тестировании Turik

## Что проверено (и как)

1. **Версионная совместимость** — проверена по официальным источникам:
   - meta.fabricmc.net: Minecraft 1.21.11 (stable), loader 0.20.1 (stable), yarn 1.21.11+build.6
   - Modrinth API: Fabric API 0.141.6+1.21.11 существует именно для 1.21.11
   - maven.fabricmc.net: Loom 1.19.3 (последний release)
2. **Архитектурные инварианты** — проверено статически на этом устройстве:
   - нет ссылки клиента на чужие GUI/рендеры: весь UI идёт через
     RenderEngine + FontRenderer (поиск по проекту DrawContext/TextRenderer
     в turik-пакетах даёт только неиспользуемые параметры-хуки Fabric API);
   - FriendManager — единственный список друзей, модули только спрашивают
     `isFriend()`/`toggle()` (поиск по `friends.add/remove` вне менеджера пуст);
   - каждый модуль зарегистрирован ровно один раз в реестре (47 записей);
   - settings сериализуются через `setValueRaw`/`getValue` для всех 8 типов.
3. **Ресурсы** — шрифт Manrope (161 KB, OFL) подключён и загружается
   `FontManager.init()` с жёсткой ошибкой при отсутствии; 5 GLSL-программ
   лежат в ресурсах и компилируются ShaderManager с логом ошибок компиляции.

## Что НЕ могло быть проверено (важно)

На устройстве разработки **нет JVM-сборки, нет запуска Minecraft и нет CI**,
поэтому:

- **компиляция не выполнялась** — риск синтаксических/маппинговых ошибок
  сосредоточен в mixin-слое и 2–3 модулях (см. LIMITATIONS.md п.2);
- **runtime-тесты не проводились**: загрузка mixin'ов, рендер GL, поведение
  модулей в игре не проверены. Методы с точечными инъекциями помечены
  `require = 0` там, где сигнатура могла измениться (InGameHudMixin),
  чтобы отсутствие цели не роняло игру;
- логи `gradlew build` необходимо получить локально; все известные
  проблемные точки перечислены и изолированы.

## Локальный чек-лист после первого `./gradlew build`

1. `renderPass` GLSL: проверить лог `[Turik] shader program '...' linked`.
2. Зайти в мир → Right Shift → ClickGUI поверх блюра, поиск, слайдеры.
3. Проверить кириллицу в поиске ("Поиск функций..."), nametags, уведомлениях.
4. Помодульный прогон по списку из docs/MODULES.md (по 1–2 минуты на модуль).
5. Повреждение `configs/active.json` → должен появиться `.damaged` и загрузка
   продолжиться с дефолтами.
